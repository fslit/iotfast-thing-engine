# 接入与用户体验规范

状态：2026-11-10 设计基线。用户确认“引擎 API / SDK 体验 + 上层管理台参考”，本轮无页面实现与视觉验收。产品定位见[产品基线](../../PRODUCT.md)，接口字段以[北向契约](../specifications/northbound-api-and-subscription-contract.md)、[遥测契约](../specifications/p0-telemetry-contract.md)、[身份契约](../specifications/service-identity-and-scope-contract.md)为准。下列 UX 状态名称是展示概念，不新增 wire enum。

## 1. 体验目标和责任

主要任务不是浏览炫酷大屏，而是完成可信接入、理解值的含义、识别异常并恢复。管理台属于 Operate（任务操作）模式，接入文档属于 Read（阅读理解）模式。引擎输出结构化事实和错误；上层完成用户认证、按钮权限、导航和展示；网关负责采集和本地重传。禁用按钮不是安全措施，引擎仍需独立校验。

| 用户任务 | 引擎必须提供 | 上层参考表现 | 不得做 |
|---|---|---|---|
| 第一次接入 | 字段约束、错误、服务认证协议、最小样例 | 有步骤和前置条件的检查清单 | 要求用户猜 tenant / Scope 或粘贴真实密钥进 AI |
| 建模与发布 | 校验结果、不可变 revision、兼容分类 | 校验定位字段，发布前显示版本差异 | 编辑已发布版本并声称历史不变 |
| 绑定来源 | 来源范围、配置 hash、激活结果 | 显示工程值归属、ACK / 停采证据 | 将配置校验通过写成设备已验证 |
| 查看实时数据 | 值、单位、时间、质量、新鲜度、连接事实 | 逐点显示状态、最后有效值及原采样时间 | 用 0 替代无值或用连接在线表示质量 good |
| 排查历史缺口 | 查询边界、目标能力、提交状态、覆盖信息 | 空结果与查询失败、部分结果区分 | 用 WAL checkpoint 推断事件时间完整 |
| 恢复服务 | 就绪状态、背压、恢复错误及脱敏关联信息 | 给出恢复步骤和影响范围 | 自动跳过 WAL 损坏后显示恢复成功 |

## 2. 首次接入旅程：必须能按文档复现

演示只使用虚构数据。推荐一个温度模型、两个设备、每设备一个属性；具体 ID / 字段由 D00 可执行 fixture 统一生成，不另复制不受校验的请求样例。

| 步骤 | 前置条件 | 动作与完成信号 | 失败后下一步 |
|---|---|---|---|
| U01 环境与身份 | 锁定版本，配置由安全通道注入 | 检查服务就绪；用有效服务身份请求被授权范围 | 无身份 / 过期拒绝；检查部署配置，不尝试自报 X-Role 绕过 |
| U02 发布模型 | management action 已授权 | 创建产品、草稿、校验、发布；得到不可变 revision | 返回字段路径和原因，修复草稿再校验；版本冲突重新读取 |
| U03 实例化 | 模型已发布 | 创建两台设备及稳定资源；同属性不串 ID | 校验资产归属及路径冲突；不得自动迁移其他设备 |
| U04 来源绑定 | 来源和设备范围可信 | 保存工程值绑定、校验；取得可信网关 ACK 或记录人工停采窗口后激活 | 未确认保持待同步；不得偷偷使用新映射解释旧数据 |
| U05 首次上报 | 已确认绑定与稳定消息标识 | 整条校验后返回实际 ACK 和 ingest_id | 422 修正整条内容；超时保留原 key 与语义重试；冲突不自动改 key 掩盖 |
| U06 查看与订阅 | 已授权资源 | 查询 latest；订阅等到 snapshot_end 后发布完整快照，再应用增量 | 初始化溢出丢弃未完成快照，显式重新同步 |
| U07 历史确认 | ingest 可查询状态 | 查看 history_status，再以半开时间范围查询；返回值携带原版本 | pending 不解释为丢失；失败 / 部分结果给出原因 |
| U08 异常演练 | 模拟环境 | 重复、乱序、坏质量、停止更新、撤权、断线恢复分别验证 | 按验收矩阵记录预期与实际；不得连生产控制做演练 |

激活绑定不等于已采到数据；收到 durable ACK 不等于历史已经可查询；看见一个点正常不等于整台设备正常。

## 3. 上层信息架构与页面交互参考

不要求新增引擎前端工程。上层可按现有平台导航承载以下六个任务区域。

| 区域 | 主信息和操作顺序 | 关键约束 |
|---|---|---|
| 模型目录 / 编辑 | 产品 → 模型版本 → 属性定义 → 校验报告 → 发布差异确认 | 发布操作显示影响范围；失败保留草稿；新版本不能隐式升级所有设备 |
| 资产 / 设备 | 授权资产树 → 设备列表 → 设备详情 | 搜索分页在服务端授权后进行；不显示无权节点数量；迁址预览稳定 ID 与新旧路径 |
| 来源 / 绑定向导 | 来源 → 模型属性映射 → 单位和转换责任 → 校验 → ACK / 停采窗口 → 激活 | 前进前校验；保留未提交内容；刷新后从服务端状态恢复，不用浏览器状态认定已激活 |
| 实时详情 | 设备身份和版本 → 连接状态 → 点表 → 最近诊断 | 点表列：属性、值、单位、质量、新鲜度、采样时间；详情展开来源 / 接收时间 / revision / 历史状态 |
| 历史趋势 | 资源 → 时间 / 时区 / 质量 → 查询 → 趋势与原始明细 | 缺口断线而非插值补齐；聚合与原始值显式区分；跨版本不兼容拒绝聚合 |
| 运行诊断 | 服务就绪 → 持久队列 / 磁盘 → 投影进度 → 最近错误 → 恢复说明 | 区分接收、WAL、历史与订阅故障；支持复制脱敏 request_id，不复制凭据或完整生产 payload |

不加入与本任务无关的告警中心、工单、用户管理、控制按钮。布局建议桌面列表 + 详情；窄屏逐项阅读、筛选可折叠，保留质量和时间等语义列，不用隐藏这些列换取“简洁”。没有已确认视觉资产，本轮不创造品牌或冻结 CSS tokens。

## 4. 数据状态呈现矩阵

这些维度可以同时出现，不能简化成唯一绿 / 红灯。

| 事实 | 必须呈现 | 禁止呈现 | 验收编号 |
|---|---|---|---|
| 从未上报 | “暂无观测”，值占位符；API 缺失值仍按契约 null | 0、false 或“运行正常” | UX01 |
| good + fresh | 值、单位、质量、新鲜度及采样时间 | 仅用动画暗示实时 | UX02 |
| good + stale | 保留值，标“已过期 / 最后观测”，原采样时间 | 把旧值更新时间改成现在 | UX03 |
| 点位 bad / uncertain | 显式质量及原因，区分最后测量与当前质量事件 | 用网关重连自动恢复 good | UX04 |
| 网关 disconnected | 网关连接异常；点位新鲜度独立计算 | 无点位证据却把所有测量质量改为 bad | UX05 |
| 未来时间异常 | 拒绝 / 隔离原因、请求关联信息 | 异常时钟刷新 latest | UX06 |
| accepted_volatile | “已接收（易失）”，说明重启可能丢失 | “已可靠保存” | UX07 |
| accepted_durable + history pending | “本地持久接收，历史处理中” | “历史已写入”或“多副本安全” | UX08 |
| 历史为空且查询成功 | “该条件下暂无已保存观测”，显示筛选条件 | “设备没有产生过数据” | UX09 |
| 历史 partial / 覆盖未知 | 保留可用结果并标部分 / 完整性未知 | complete 标签或补零连线 | UX10 |
| 订阅重连 / resync | 标“同步中”，最后画面带断连状态；完整快照后替换 | 初始化半个快照作为完整当前状态 | UX11 |
| 无权限或不存在 | 统一“资源不可用”，遵循服务端隐匿语义 | 告知资源真实存在、名称或未授权数量 | UX12 |

## 5. 交互、错误与重试契约

- 所有异步操作覆盖初始、加载、成功、失败、空、范围变化、超时状态。失败不清空仍合法的用户输入；提交中防止重复点击，但不能替代服务端幂等。
- 展示可安全公开的错误码、字段路径、原因、建议动作和 request_id；详情脱敏。认证错误提示更新身份配置，不显示签名密钥、授权全集或他域信息。
- 422：用户修复请求后新业务操作；409：区分版本冲突和幂等冲突，先读取当前状态 / 原请求，不盲目重复。
- 429 / 503：仅在契约允许 retryable 时按 retry_after 和上限退避；网络超时是结果未知，不等于接收失败。遥测重试沿用原 message_id、epoch、seq 和语义 payload。
- 控制面超时不能假定安全重试；先按已冻结幂等协议查询结果。尚无协议的操作必须在 D00 补齐后实现自动重试。
- WS 撤权、过期和 resync 后停止消费旧会话；旧 cursor 不自动迁移到新身份。重新鉴权不扩大可见范围。
- 用户时区仅影响展示和时间选择；请求使用契约要求的 UTC Unix 毫秒，历史范围明确 `[start,end)`。展示绝对时间和时区，可辅以相对时间。
- 大整数和序列保持十进制字符串，不经 JavaScript Number；数值格式化不能回写测量精度；单位转换如属展示层须明确，不改变原始事实。

## 6. API 文档与 SDK 的交付要求

P0 不先承诺发布多语言 SDK。先交付经测试的 HTTP / WS 契约和最小客户端示例，再按首个实际消费方选 SDK。

每个端点文档包含：调用服务类别、action / Scope、请求 / 响应 Schema、必填和未知字段政策、大小限制、正例与反例、错误码、幂等与重试、超时、分页一致性、能力限制及版本策略。样例必须与 Schema 自动校验，不能只通过 JSON parse。

最小示例包含：安全读取测试凭据、建模与绑定前置 fixture、一个合法遥测、同 key 重试、history pending 处理、严格快照订阅、断线重同步和脱敏错误输出。示例不能硬编码生产地址，不能关闭证书校验，不能从 AI 文本构造 Scope 或 SQL。

## 7. 可用性验收与交接

体验验收使用上述 U01–U08 和 UX01–UX12，报告写明是 API 客户端测试、上层页面测试还是规范审查。P0 引擎以返回事实正确为验收，页面验收在上层项目单独签收。

建议上层验收：键盘走完整个向导；字段错误能定位；状态文字与非颜色标识并存；长资源名可完整访问；缩放和窄屏不丢质量 / 时间；加载、空、失败、过期、部分权限、重连状态均有可复现 fixture。无页面实现时这些项标“未执行”，不得用文档评审代替可用性测试。

待现场确认：首个上层系统、实际点表、常用设备 / 点数、语言与时区、支持的浏览器、用户任务耗时目标。缺这些输入不阻塞纯引擎模拟测试，但阻塞现场 UX 签收。
