# TDengine IDMP 理念评估与本引擎应用设计

状态：产品 / 架构参考，2026-11-05。依据 TDengine IDMP 官方公开文档；下文对本项目的判断是设计建议，不表示已实现或已验证。最终用户 / 角色与业务权限仍由上层承担，服务身份验证及可信数据范围由引擎执行。不得把“参考理念”表述为兼容 IDMP，也不得照搬未核实的行为和性能承诺。

## 1. 判断

IDMP 值得参考，尤其是资产语义组织、模板复用、属性数据引用、树加关系网络和模型驱动的指标定义。它不仅是设备点位表，也把设备、产线、工序和业务指标组织为上下文化的数据资源。

本项目目标更聚焦：作为 **IOT-Fast 设备业务数据模型与标准数据服务引擎**，为八位魔方 / SCADA / MES / EMS / AI 提供资源、实时 / 历史及可追溯指标；不复制 IDMP 的页面、用户管理、完整规则平台或自动控制。

## 2. 官方概念与应用判断

| IDMP 文档概念 | 官方资料中的作用 | 我们的建议 | 优先级 |
|---|---|---|---|
| Element / Attribute | 资产对象及其属性，厂、线、设备等均可为对象 | 设备属性以外，让产线、工序、能源系统作为逻辑资产，逐步具备指标；设备保持现有 device_id | P0 模型补充，产线指标 P1 |
| Template / Attribute Template | 模板定义属性并实例化，支持复用 | 复用现有产品 / 模型版本体系，设计面向其他对象的可选模板，不能默认改写已发布版本 | P0 明确规则 |
| Data Reference | 将语义属性关联度量、静态值或计算等 | 把当前 gateway 绑定抽象为版本化 AttributeSource；先做工程值输入；外部直读另设能力 | P0 抽象，直读 P1 探针 |
| Contextualization | 单位、描述、位置、关系和上下文 | 标准语义、量纲、数据质量、来源、有效期和业务上下文 | P0 |
| Tree + Network | 资产层级与额外引用构成关系 | 主树仍为浏览 / UNS；工艺、供电、供水另用类型化边；不要求引入图数据库 | P1 |
| Analysis / KPI | 对属性按窗口 / 事件触发计算 | 通用衍生数据与指标契约；OEE、能源业务规则及确认由 MES / EMS 专业服务承担 | P1 简单计算，P2 业务算法 |
| Event | 带时间及上下文的生产或设备事件 | P1 可纳入外部事件事实及来源；告警确认、通知、工单留给上层 | P1 设计，非 P0 必需 |
| Zero Query Intelligence | 基于上下文建议分析 / 可视化 | 引擎提供语义与质量；主动洞察 / AI 应用在上层，建议需提供证据且不可直接控制 | 上层后续 |
| 数据源反向建模 | 从数据源结构辅助生成资产模型 | 候选草稿、差异预览、人工确认和回滚；不能根据表名自动创建生产配置 | P2 |

以上是结合文档形成的选择，不代表 IDMP 支持本项目全部部署形式或与本项目的术语完全一致。

## 3. 对象与资产建模

保留 product、model_revision、device、resource 的现有语义，不为了模仿 IDMP 将 device 改名或破坏既有接口。引入统一逻辑资产 Asset：可为企业、厂区、产线、工段、设备或能源系统；P0 保留原资产树与设备引用，P1 研究线级 / 能源级资源归属。

- 一条主树用于浏览和 UNS canonical path；主树不允许环，device / resource ID 不因路径变动而变化。
- 跨树关系以稳定 ID 和关系类型表达，例如 FEEDS、UPSTREAM_OF、MEASURED_BY、PART_OF；关系可附方向、生效区间和可信来源。
- 关系仅表达“已建模的关联”，不自动证明物理流向、因果或可控制性。环校验按关系类型决定；拓扑错误不得变成 AI 的事实依据。
- P1 可先用关系表及索引完成常用查询；多跳规模、实时更新和图数据库需求在实测后决定。
- 关系可见性必须受上层传递的可信数据范围约束；被遮蔽的端点和边不应通过计数、遍历或错误暴露。

### 资产关系扩展表（逻辑草案）

asset_relation：tenant_id、relation_id、from_asset_id、relation_type、to_asset_id、valid_from_ms、valid_to_ms、source、revision。类型词表、重复 / 环 / 删除约束和多租户复合键待冻结。P0 不实施该表；无固定关系版本时历史计算无法推断当时拓扑。

## 4. 属性数据引用与复用

现有 P0 绑定是网关完成工程量转换后上报，保持不变。扩展为语义属性引用多种来源的统一描述，按阶段分别提供：

| source_kind | 来源 | 当前状态 / 限制 |
|---|---|---|
| gateway_measurement | 已接入网关的标准工程值 | 当前 P0 目标；不得二次换算 |
| static_config | 型号参数、资产属性 | 须版本化和指定有效时间；不是实时观测 |
| derived_metric | 简单计算结果 / 外部算法结果 | 遵循衍生指标与血缘规范；不冒充实测 |
| external_reference | 已有时序库 / 关系库的历史或当前值 | P1 可行性验证；并不意味着已支持任意表 / SQL |
| external_fact | MES / EMS 传入的业务事实 | 来源、范围、质量与版本明确；上层负责业务权威性 |

示例：同为 outlet_pressure，泵 A 通过网关映射、泵 B 将来可引用已有历史数据源；二者被上层按相同语义发现，但必须在数据来源、采样时间与质量上可区分，禁止把没有质量的旧值默认为 good。

数据库外部引用有不同的查询一致性、时间精度、字段类型、持续订阅、授权和丢失语义。未经验证不得宣称可实时推送、无副本同步或跨库等价。只支持受控连接和受限查询，参数绑定与标识白名单；不把模型中的字符串当任意 SQL 执行。连接凭据使用引用而非暴露在模型或 AI 上下文。

### 读既有数据与自管历史的边界

官方介绍称 IDMP 的模型层管理上下文并从 TSDB 获取时间序列。本项目已有本地 WAL 与 DuckDB 历史设计，不能直接推导为与 IDMP 相同的存储行为。后续可评估：
1. managed_ingest：网关 → 引擎 WAL → DuckDB / 外部库。
2. referenced_read：外部数据库保有原始数据，引擎以只读引用查询；不会自动拥有写入、回放、实时订阅或数据副本。

两模式每个属性绑定需要明确权威来源、可用性 / 一致性和历史保留；不能把两者无标识 UNION 后称为完整数据。已有 DuckDB 默认和 WAL 可靠性计划不变，reference 能力需单独选型与测试。

## 5. 模板变更：借鉴复用，维持可控版本

官方文档描述模板及实例属性复用，某些配置变动可同步实例。本项目现有约束是**模型发布版本不可变**，不默认自动修改已部署设备；借鉴一次建模多实例，而非直接复制自动传播行为。

1. 模板草稿校验 → 发布不可变 revision。
2. 设备引用具体 revision，现场地址在独立绑定快照。
3. 新版本产生差异报告，检查资源 ID、单位 / 类型 / 语义、下游订阅、历史与绑定。
4. 选择适用实例分批迁移，网关确认绑定生效；无法确认则停采窗口。
5. 旧数据保留原模型版本 / 绑定版本，失败设备可停止迁移并可按已发布版本回滚。

产线 / 能源对象的模板复用、继承、冲突解决、删除和批量迁移属于后续独立设计；不能因为模板属性新建就自动生成大量设备资源或假定统一设备地址。

## 6. 指标、事件与业务模型

### 6.1 OEE 和能耗

引擎负责提供符合模型的设备运行状态、电表、产量等数据与质量；上层 MES 提供班次、工单、理想节拍、产量 / 良品；上层 EMS 提供节能基准、能源边界和评价口径。可选计算服务输出 derived_metric，按指标定义 / 算法版本 / 生效绑定 / 窗口存档，并返回输入血缘和质量。

OEE 不足的数据应显示 unknown / uncertain 而非 0；能耗应处理电表清零、回卷与换表；预算与节能结论不能在缺少基准、工况和统计证据时自动下结论。现有 [OEE 与能耗规范](../specifications/derived-metrics-oee-energy.md) 继续适用。

### 6.2 事件

事件事实（如某设备出现一次状态区间）可由上游或未来计算服务提供：event_id、事件类型、资产 ID、开始 / 结束时间、来源、模型版本、上下文快照、质量 / 修订。事件和报警流程分离；本引擎不处理用户确认、通知或工单。无权范围和敏感字段不得通过事件血缘泄露。

## 7. 对 AI 原生的实际价值

向上层 AI 提供受控、可追溯、可检索的：
- 资源标识与路径、可读名称、模型版本、用途和单位。
- 当前值 / 时区 / 时间 / freshness / quality，是否实测或计算及来源。
- 已核实的资产关系、数据来源、指标定义与输入依赖。
- 根据调用服务授权后的可见范围，以及缺失数据 / 可信度信息。

上层 AI 基于这些资料推荐可能的 OEE 或能耗分析，展示来源与质量并由业务人员确认。语义标签、设备备注和 AI 建议均不是权限、安全联锁或真实事实的替代。不得通过向量相似度推断设备状态、自动调整 PLC 或虚构数值。主动洞察属于上层应用而不是 P0 引擎职责。

## 8. 端到端示例：车间双泵与能耗

厂区 → 水泵房 → pump-001 / pump-002 为主资产树；两台泵使用同一发布模型，各自绑定网关采集 pressure / power / energy_total。另以 MEASURED_BY 类型将水泵房关联公共电表，以 FEEDS 记录审核确认的供水关系。

引擎按设备、产线、能源资产提供标准属性与质量；EMS 使用经确认的电表累计量和生产 / 运行上下文计算窗口能耗、待机能耗线索或单位产量能耗，结果作为 derived_metric 返回并注明所属能源资产、窗口、算法、输入与版本。公共电表不能自动归因到每台泵：分摊系数、交叉边界和重叠计量必须由 EMS / 现场明确。

## 9. 验收和技术验证

- IDMP-01 模型同版本创建两台设备，属性语义一致，来源与 resource_id 不同，工程值不重复转换。
- IDMP-02 主树移动后 resource_id 和历史不变；关系只暴露授权范围，历史关系按有效期解释。
- IDMP-03 新模型发布不会自动更改已部署设备；迁移按绑定版本、差异和网关确认执行。
- IDMP-04 static / gateway / derived / external 的来源和时间质量不可混淆，缺失不补 0。
- IDMP-05 外部库断网或数据有延迟时显示 unknown / stale 或错误，不宣称实时连续或本地持久。
- IDMP-06 派生指标输入质量不足、迟到或更正，结果及修订可追溯；OEE 与能耗在不同窗口 / 业务口径不得误合并。
- IDMP-07 上层 AI 只读取授权范围内的语义和证据，不具备控制接口。
- IDMP-08 从历史库导入模型须生成草稿 / 差异预览和校验报告，禁止未经确认投入采集或覆盖既有映射。

所有测试均待执行。P0 优先交付模型 / 实例 / 采集绑定 / 业务视图及数据质量；关系网络、外部直读、模板批量导入和事件为后续分期，按真实客户场景决定。
