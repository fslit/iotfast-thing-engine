# 衍生指标、OEE 与能耗算法和设备模型结合设计

状态：设计草案；未实现算法、接口、表或实测。职责以 [数据引擎定位](../architecture/data-engine-scope.md) 为准。设备模型和实时数据以 [设备业务模型](device-business-model.md) 为准；本文件的端点、报文、表和数值均为示例，正式 Schema / 安全 / 性能需另行冻结验证。

## 1. 目标及分层

使设备模型不仅描述采集属性，也能描述可追溯的**衍生指标**；统一采集值、简单公式结果与外部专业算法结果的发现、质量、版本、查询和展示方式。

| 职责 | 数据模型引擎 | 上层 MES / EMS / 独立算法服务 |
|---|---|---|
| 模型 | 定义属性 / 指标、单位、输入输出契约及资源定位 | 确认行业语义、口径与适用范围 |
| 数据 | 标准化采集、时间质量、实时 / 历史数据 | 提供班次、排程、订单、工艺、产量 / 合格品等业务事实 |
| 计算 | 可扩展的受限计算能力；P1 先实现简单确定性派生 | OEE 业务口径、基线模型、节能策略和复杂计算优先留在专业服务 |
| 结果 | 接收、校验、存储与提供带来源的结果 | 消费结果，生成业务报告或建议 |
| 权限 / 控制 | 校验服务身份与可信范围；不管理用户 / 角色 | 业务授权、节能措施评审与设备控制 |

这是计算能力的设计，不表示将 MES / EMS 全部集成进引擎；不使算法自动下发设备命令。系统是否安装独立算法服务可配置，P0 现有采集闭环不依赖它。

## 2. 模型如何表达计算属性

产品模型的属性增加来源类型（详细字段命名和 Schema 待 D00 评审）：

| 来源 | 例子 | 值由谁产生 |
|---|---|---|
| collected | 电表累计电量、运行状态 | 网关采集并上报 |
| static | 设备额定功率 / 生产线编号 | 已批准的设备静态配置，变更需版本与生效期 |
| derived | 瞬时压差、窗口平均功率 | 受限计算执行器或经过授权的外部计算服务 |
| external_fact | 排班、计划停机、产量、良品数 | MES 等提供，需来源 / 权威性 / 时间 |

derived 仍是可定位资源；输出携带 value、unit、quality、采样 / 窗口时间、计算状态、算法 ID / 版本、配置版本及来源快照引用。引擎不能把估计值 / 插值标成实测值。静态参数和外部事实在时间上也有版本与有效区间；例如旧班次 OEE 不得默认用今天的额定节拍重算。

## 3. 算法定义、绑定和实例

1. **MetricDefinition**：定义输出 identifier、类型、单位、语义、粒度（点 / 窗口）、质量策略及适用模型；不包含现场 device_id。
2. **AlgorithmRevision**：算法 ID、不可变版本、输入 / 输出类型、单位、计算方法、执行位置、窗口 / 触发、质量规则、可重复性及依赖清单。
3. **MetricBindingRevision**：针对设备 / 产线 / 能源对象绑定输入 resource_id / 外部事实、配置、输出 resource_id 与生效区间；缺少依赖不得激活。
4. **CalculationRun**：记录按哪一算法版本、绑定、窗口、数据水位和实际输入版本执行，及结果、错误与血缘。
5. **MetricResultRevision**：针对同一指标 / 对象 / 窗口的结果修订；晚到、人工更正或算法升级触发重算时生成新修订而非覆盖审计历史。

算法定义归引擎的通用数据契约；某个客户的生产规则 / 权重 / 节能判断归上层并以受信版本传入或由外部服务执行。算法发布、绑定、观测校验和输出可由独立团队分别实现。

## 4. 输入依赖、时间和质量

计算前验证资源归属与可信服务范围、类型与量纲、模型和绑定版本、时间范围、质量、完整度及计算 DAG 无循环。被授权写入计算结果的服务身份与作用范围须独立校验；上层业务用户权限仍由上层执行。

- 输入缺失、bad、stale、窗口覆盖不足，按算法声明拒算 / 输出 unknown / uncertain；不能默默将缺失值变为 0。
- 实时公式需声明最大时间偏差 / 数据有效期。两点采样时刻差过大不能被视为同一时刻的准确测量。
- 周期指标使用 [start,end) 和项目时区 / 班次版本；保存 UTC 时间，跨午夜 / 夏令时的班次边界按项目日历解析并测试。
- 回填 / 乱序 / 更正需设允许迟到时间、窗口结束后延迟结算规则和修订策略。final 表示当前规则下结算，不表示未来绝不修正。
- 数值有效范围、分母为 0、非有限数、单位换算和取整必须显式配置；不能默认截断到 0–100% 以掩盖异常。
- 输入依赖和输出不得形成循环；历史更正和重算需进行去重 / 版本控制，避免把结果作为新采集值重复触发无限计算。

## 5. OEE：与设备模型及 MES 结合

### 5.1 采用可配置口径

OEE 常见定义为可用率 × 性能效率 × 质量率；具体口径由现场确定，计划生产时间、停机、生产数量、良品和理想节拍的来源应在配置和结果中公开。不是所有生产线的 OEE 都适合把各设备 OEE 简单平均；产线口径由上层定义。

| 指标 | 本文示例公式 | 所需事实 |
|---|---|---|
| 可用率 A | 实际运行时间 / 计划生产时间 | 设备状态与班次、计划停机口径 |
| 性能效率 P | 理想周期 × 总产量 / 实际运行时间 | 产品或工单理想周期、总产量、运行时间 |
| 质量率 Q | 合格品数量 / 总产量 | 总产量、良品或报废统计 |
| OEE | A × P × Q | 以上有效结果与相同窗口 |

计划生产时间是否扣除计划停机必须明确且不能重复扣减；运行 / 停机状态映射须基于现场经审核的状态模型。多品种时不能套单一节拍，需按工单 / 产品在重叠区间分别累计理想生产时间，再依据约定汇总；返工 / 报废 / 良品统计也需明确。分母为 0 返回不可计算及原因。

### 5.2 具体例子

假设某生产单元在某班次：计划生产时间 480 分钟（已按现场口径处理计划停机）、实际运行 400 分钟、理想节拍 0.5 分钟 / 件、总产量 720 件、良品 684 件：

- A = 400 / 480 = 83.33%。
- P = 0.5 × 720 / 400 = 90.00%。
- Q = 684 / 720 = 95.00%。
- OEE = 83.33% × 90.00% × 95.00% ≈ **71.25%**。

只是计算演示，不表示该设备实际 OEE。计划时间和理想节拍等业务上下文必须由上层提供并保存版本。

### 5.3 数据映射

设备模型提供设备运行状态 / 故障状态和计数等已标准化资源；MES 提供班次日历、工单、产品、产量、良品和理想节拍。OEE 算法服务经授权查询指定窗口的数据，形成产线或设备级 OEE 结果并携带输入来源与版本；引擎验证结果契约后提供给上层。计算责任方由绑定指定，不在引擎与 MES 中重复计算并各自声称权威。

运行 / 停机时长不能简单用首末状态推断：状态按时间排序并切分时间段，窗口开始需要边界状态；缺失、bad、数据迟到或边界状态未知形成 unknown duration。建议报告计划时间、运行时间、未知时间及数据覆盖率；只有覆盖 / 质量满足项目配置才输出有效 OEE，否则返回 uncertain 或不可计算。

## 6. 能耗与节能：电表模型及 EMS

### 6.1 能耗数据模型

| 数据 | 推荐资源 | 单位 | 要点 |
|---|---|---|---|
| 累计电能 | energy_total | kWh | 累计表读数，记录抄表时间、倍率和表计版本 |
| 瞬时功率 | active_power | kW | 来源是采样功率，非直接等于能耗 |
| 产量 | production_count | 件 | 可由设备采集或 MES 提供，确定权威源 |
| 区间耗电量 | energy_consumption | kWh | 有效期末累计值减期初累计值 |
| 单位产量能耗 | specific_energy | kWh / 件 | 区间耗电量 / 合格产量，分母口径需固定 |

**优先使用已确认的累计电量差值**；读取边界不刚好有采样时应明确采用前值、插值或不计算，标记数据覆盖 / 估算。电表清零、回卷、换表、倍率变化、重复与迟到必须有事件或规则；不能对负差值简单取绝对值。电能从功率计算时应采用经声明的积分方法、采样间隔、缺失数据与精度策略，例如 kW × 小时 = kWh；这可能是估算。

### 6.2 能耗示例

窗口期初电表 10,250 kWh、期末 10,730 kWh，期间确认未清零 / 换表，则耗电 **480 kWh**；同时合格产量 800 件，单位合格品能耗为 **0.60 kWh / 件**。真实应用需核对倍率、读数时间、数据质量与能耗 / 产量统计边界。

### 6.3 节能判断与测量核算

上层 EMS 可用相同生产对象、相同统计口径的历史单位能耗建立基准，按温度、工况、负荷、品种或产量做必要调整；模型引擎提供标准观测及版本。建议值可以输出“待机能耗偏高”等**线索**及证据，上层专家决定是否采取措施。节能量不能由未经对照的两段总电量直接证明；需声明基准、调整、边界、数据质量、估算方法与不确定性。

## 7. 指标模型与数据结构草案

以下为示意，不是最终协议，也未确定实际 SQL 表：

| 逻辑表 | 关键字段 / 关系 | 不变量 |
|---|---|---|
| metric_definition | metric_id、identifier、name、value_type、unit、scope_type、semantic | 指标定义不保存当前值 |
| algorithm_revision | algorithm_revision_id、algorithm_key、version、input_spec、output_spec、method、quality_policy | 发布版本不可变 |
| metric_binding_revision | binding_revision_id、algorithm_revision_id、scope_id、input_bindings、config、effective_from / to | 每项引用的资源 / 外部事实有生效范围 |
| calculation_run | run_id、algorithm_revision_id、binding_revision_id、scope_id、window_start / end、watermark、status、inputs_digest、started / finished | 记录实际输入、失败和重算原因 |
| metric_result_revision | result_id、scope_id、metric_id、window_start / end、revision、value、unit、quality、coverage、run_id、supersedes_result_id | 一个计算窗口可有多个结果修订 |
| metric_lineage_ref | result_id、input_resource_id / fact_ref、input_version / snapshot、time_range、quality_summary | 以可控粒度保存血缘引用，避免默认逐点复制 |
| metric_latest | scope_id、metric_id、result_id、updated_at | 仅作为最新视图，可从结果修订恢复 |

现有模型和历史表与这些表的归属 / 事务需在物理设计阶段明确。结果幂等键建议绑定 tenant、scope、metric、窗口、算法版本、绑定版本、输入水位 / 修订；同请求重试不能生成冲突事实，输入更正 / 版本变化可产生新 revision。精确规范化算法和哈希规则待冻结；不同存储之间不假设分布式事务。

## 9. 开放接口方向

- 算法 / 指标目录：按模型和资源发现指标定义、输入输出和单位。
- 绑定与配置：为具体设备 / 产线映射输入资源与上层事实，发布不可变绑定快照。
- 计算请求与结果接入：由受信算法服务提交窗口结果和证据；去重、来源授权、冲突和修订必须验证。
- 查询：按资源 / 范围 / 时间查看指标最新与历史、quality、状态、版本及血缘；敏感业务数据遵循可信范围。
- 重算：记录原因、版本、数据快照和影响窗口，形成新 revision；告知订阅方结果被修订。

上述是接口方向，不代表已开发；服务断网或未配置外部事实时，不允许引擎自动填补上层业务数据。

## 10. 验证与实施优先级

1. P0：采集点、模型版本、标准时间质量和历史可查；不依赖 OEE。
2. P1：单设备确定性公式（如压差、窗口统计）及衍生属性 / 质量 / 血缘；完成 BM 测试后接入。
3. P2：MES 外部事实 + 班次 OEE、异常时段覆盖与结果修订；由业务方签认公式口径。
4. P2：累计电量差、清零 / 换表识别、单位产量能耗和质量标记。
5. 后续：外部 EMS 基线、节能线索和可追溯结果；具体节能核算需要经现场确认的测量与业务方法。

验收向量：OEE 示例得 71.25%；无计划时间 / 总产量为 0 不除零；时间覆盖不足不输出 good；混产品按具体订单节拍分段；电表重置不能取负差绝对值；晚到数据触发结果修订；重复输入 / 重算无重复事实；不同项目的数据范围隔离；单位不兼容拒绝；仅当版本与输入一致才可重现结果。上述均为待执行测试，不是已实现能力。
