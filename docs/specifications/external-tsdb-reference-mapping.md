# 外部时序库引用与设备模型映射详细设计

状态：设计草案，未实现 / 联调。本文细化 [TSDB 统一与扩展接口](tsdb-common-extension-interface.md)、[资产模板与数据引用](asset-template-and-source-reference.md)；职责边界遵循 [数据引擎定位](../architecture/data-engine-scope.md)。示例均为假设，不代表已支持具体数据库版本。

## 1. 目标与边界

已有工厂可能将设备数据保存在第三方数据库，其物理字段不符合本引擎的统一设备模型。引擎通过**受控数据引用**，把一组外部记录解释为设备资源的历史 / 最新数据，让上层按照 resource_id 使用标准查询。

外部引用是 referenced_read：原始数据仍在外部库，引擎读取并按绑定规则解释。它不自动获得 managed_ingest 的本地 WAL、设备上报确认、实时订阅、历史副本或断网补传语义。P0 已确定的网关工程值上报不变；本文属于 P1 的设计和可行性验证，不代表已经修改 P0 单设备一个 active 绑定的规则。

## 2. 最小业务示例

一个型号的两台泵，设备模型都有 outlet_pressure、active_power：

| 资源 | 外部来源 | 物理引用（假设） | 转换 | 标准值 |
|---|---|---|---|---|
| pump-001/outlet_pressure | TDengine 数据源 A | 设备子表 / ts / pressure_kpa | kPa → MPa，乘 0.001 | 420 → 0.42 MPa |
| pump-002/outlet_pressure | 数据源 A | 另一个设备子表 / ts / pressure_mpa | 恒等 | 0.42 MPa |

以上仅说明映射，不断言某产品特定版本 / 连接方式已支持对应能力。单位、倍率和来源数据质量必须经现场核对；外部数据如果已是 MPa 不再应用重复转换。P0 网关工程值路径仍不由引擎二次换算；P1 referenced_read 的受控转换是独立能力及执行策略。

## 3. 对象及版本

| 对象 | 职责及身份 | 不变量 |
|---|---|---|
| SourceConnection | source_connection_id、目标类型 / 版本、网络端点引用、凭据引用、schema / catalog 范围、只读配置版本 | 不把密码嵌入模型、日志或 API |
| SourceCapabilitySnapshot | 连接和适配器版本、部署配置、支持能力、证据、检查时间 | 更新连接 / 库版本或失效条件发生时重新验证 |
| SourceObject | source_connection_id、目标原生命名空间、对象类型、对象名及结构摘要 | 只可从可信发现或显式核验结果中选取，不能拼接任意用户 SQL |
| AttributeReferenceRevision | reference_revision_id、resource_id、source_connection_id、源对象 / 字段 / 限定条件、时间 / 类型 / 单位 / 质量 / 转换与有效期 | 发布快照不可变；历史结果需说明实际解释版本 |
| ReferenceActivation | reference_revision_id、业务有效区间、记录时间、配置修订和验证状态 | 同一资源的同一权威角色有效时间不能含糊重叠 |
| QueryPlan | 已授权资源、固定映射版本、选定目标、类型检查、执行位置和限制 | 不能跨越调用方可信范围 |
| ReferenceHealth | 最近检查、最后成功读取、状态和源水位（若可证明） | 健康不代表当前数据新鲜 / 历史完整 |

logical reference 与既有 binding_revision 必须在设计冻结时定义从属关系及事务范围；不能为同一资源同时形成两套相互覆盖的权威绑定。跨数据库直读 P1 如需复用当前设备绑定，应新增可区分的版本化引用记录并明确设备与资源的有效区间；不能宣称现有 P0 已支持。

## 4. 数据源连接配置与发现

数据源只能由经过服务身份及可信范围验证的上层管理服务配置。连接配置含适配器类型、版本 / 模式、连接目标、专用只读凭据引用、可访问数据库 / 对象白名单、超时、扫描上限和 TLS 约束；实际可访问性还依赖网络及数据库侧授权。不能仅凭 UI 白名单替代数据库权限。

发现是可选功能：读取目标库可用元数据，返回数据库 / schema / 表或序列、字段、类型、时间字段、标签及发现时间；在授权范围内显示。缓存包含 schema fingerprint / version；目标结构或凭据、版本发生变化时失效。无 metadata 权限时允许使用经人工验证的受限对象描述，标记未发现 / 已核验的差别。

重要：来源查询不能接受自由 SQL、任意 URL 或路径模板；schema、table、column、tag 等物理标识必须来自白名单 / 验证结果，通过目标适配器的安全引用机制构造；值参数使用参数绑定。高基数标签和目标库扫描成本需估算，避免一条界面查询拖垮现场库。确有特殊数据分析需要时走另行设计的受控扩展接口。

## 5. 映射草案

```json
{
  "reference_revision_id": "ref-pump001-pressure-r1",
  "resource_id": "res-pump001-pressure",
  "mode": "referenced_read",
  "connection_id": "source-a",
  "source": {
    "namespace": "factory_ts",
    "object": "pump_001",
    "timestamp_field": "ts",
    "value_field": "pressure_kpa",
    "quality_field": null
  },
  "value_type": "float64",
  "source_unit": "kPa",
  "target_unit": "MPa",
  "transform": {"kind": "linear", "factor": 0.001, "offset": 0.0},
  "quality_if_missing": "unknown",
  "valid_from_ms": 1793865600000,
  "valid_to_ms": null
}
```

配置只示意逻辑，不保证指定数据库 / 驱动可表达此物理结构。namespace / object / field 均须经来源对象白名单校验，转换来源及量纲须由现场确认；单位采用已审定词表。未配置质量列时返回 unknown，不接受用户把缺失质量强行声明 good。引用模式下没有真实接收时间 / observation_id 时不能伪造；不得把读取时刻标记为采样时刻。

## 6. 类型、单位和质量转换

执行过程：解析数值与源时间 → 检查源质量和类型 → 按已发布版本执行受控转换 → 检查目标类型 / 量纲 / 范围 → 组装标准结果并标明来源、映射版本与精度。

- 只提供明确注册的转换，首次考虑 identity、线性 / 经过认证的单位换算、枚举映射；不运行用户脚本或自由表达式。
- 计算系数、offset 和单位归属必须明确；同一条路径只转换一次。不能因为显示单位变化悄悄修改保存值。
- 数值溢出、非有限数、未知枚举、类型不兼容时标为错误或拒绝，不变成 0 / 正常质量。
- 数据源没有质量列 → unknown；质量列保留原始值及映射版本；stale 依据最后采样时间和策略单独计算。
- 时区 / 时间来源和精度应声明；仅有秒级时间时不能生成未经证明的毫秒级采样信息。
- 涉及范围变换时，不能简单比较转换前数据与目标单位阈值；先统一量纲再校验。

转换下推仅当可以证明后端运算与引擎语义在类型、溢出、NULL、精度及单位方面一致；否则安全地在结果上转换或拒绝。存在降采样 / 截断时要对上层披露。

## 7. 查询执行与能力判断

流程：请求资源和时间 → 认证服务身份并执行可信数据范围 → 在读快照中确定 reference revision / 有效区间 → 筛选目标后端的能力快照 → 类型 / 单位 / 质量与限制检查 → 生成受限查询计划 → 执行并转换 → 返回覆盖范围及限制。

| 请求 | 已具备能力 | 无法满足时 |
|---|---|---|
| 最新值 | 有可验证排序与采样时间 | 无数据和源不可用区分；无质量返回 unknown |
| 原始历史 | 可表达时间窗口、授权过滤、排序和安全分页 | 标记弱一致 / partial 或在严格模式拒绝 |
| good-only | 质量可验证映射 | 无质量时不能把 unknown 算 good；严格查询拒绝 |
| 聚合 avg | 数值 / 单位兼容且窗口与质量语义可证明 | 允许受限原始值拉取 + 引擎计算时明确标注，否则拒绝 |
| 实时订阅 | 源和适配器经测试提供连续变更 | 否则可选轮询并明确遗漏窗口 / 延迟，不冒充无缺口订阅 |

外部库直接查询和本地历史不自动合并。确需跨源查询时检查每条数据身份 / 时间范围 / 去重和授权范围；无法证明完整性必须拒绝精确模式或返回 partial + warnings。watermark 只有来源能证明时才返回，不得以当前时钟充当已完整的水位。

## 8. 绑定变更与时间区间

引用快照按 [valid_from,valid_to) 解释；切换策略必须区分**采样事实时间**与**配置记录时间**：

1. 先以只读测试连接验证权限、字段、类型、时区、历史 / 当前样本与 quality，形成测试报告；测试结果不自动激活。
2. 对同一资源 / 权威角色预览时间区间重叠、历史已有绑定、单位语义和设备模型的差异。
3. 条件版本检查并在元数据事务中激活新快照、结束旧快照；时间边界由操作方明确，不得自动改写历史事实。
4. 历史查询跨越切换点时按各绑定有效区间分段查询，并返回来源与映射版本；若旧源不可用或物理数据已改变，明确 gap / partial。
5. 事后修正映射需要形成新的配置记录和审计，不能覆盖旧版本并声称能精确恢复曾看到的数据。是否支持回溯修订及其双时间语义在开发前另行冻结。

若源库会修改 / 清理历史，版本化映射本身不能重现历史值；需要源侧不可变快照、保留策略或引擎持久化副本，且需另行验证。一个逻辑设备属性不能在同一角色和时间同时存在两个未定义优先级的权威来源。

## 9. 候选对外契约

接口路径均为待冻结草案：来源连接 / 能力检查、来源结构发现、引用草稿 / 校验 / 预览 / 激活、资源 latest 与 history。规范响应至少包含 request_id、resource_id、source_connection_id、reference_revision_id、source_mode、时间 / 质量与时区、是否转换、coverage、partial、warnings、consistency、cursor。错误类型至少区分 SOURCE_UNAVAILABLE、REFERENCE_INVALID、UNIT_INCOMPATIBLE、QUALITY_UNAVAILABLE、CAPABILITY_UNSUPPORTED、QUERY_LIMIT_EXCEEDED、SCHEMA_DRIFT；外部响应不能返回数据库密码、驱动栈或其他租户存在性信息。

本引擎只验证服务身份、可信数据范围和资源边界；用户 / 角色和业务授权仍属上层。

## 10. 运维与验收

监控连接状态、最后成功读取、响应耗时、超时 / 限流、schema drift、映射失败、转换错误、未知质量比例和目标库配额；避免高基数标签泄露客户数据。

- R01：两台泵不同库 / 不同单位映射到同一模型，输出分别正确、没有二次转换。
- R02：没有质量列时 quality=unknown；good-only 严格查询不能声称完成。
- R03：源关闭 / 超时时明确 unavailable 或 partial；最后值保留原采样时间，标记 stale。
- R04：请求跨引用切换时间，按各自 [from,to) 分段；旧源缺失暴露 gap。
- R05：源表结构、类型或权限变更使能力快照失效，不能继续套用旧映射当作已验证。
- R06：只有秒级时间 / 缺失 observation_id 时不伪造精度、身份或去重保证。
- R07：未经授权的资源、数据库对象及关系不可访问；参数中自由 SQL / 越权标识拒绝。
- R08：源更新历史后，无快照机制时不得宣称历史结果可重现；保留条件需外部证据。
- R09：聚合在目标或引擎执行时比较 NULL、单位、质量和窗口，超过预算拒绝而非无限读取。
- R10：订阅退化为轮询时明确类型和丢失可能，不能宣称事件完整。

先以一套虚构的只读源进行契约与失败模拟，再选择现场实际使用的一种 TSDB 做版本锁定的 PoC；每项需保存数据样例、环境、驱动 / 服务器版本、测试结果及缺口。当前所有验证均未执行。
