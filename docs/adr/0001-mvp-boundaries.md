# ADR 0001：首期架构与交付边界

状态：设计建议，待真实工程和现场输入验证。

## 背景

八位魔方 / IOT-Fast 需要统一设备模型、资源定位和数据契约，同时已有现场采集网关与 Node-RED 生态。

## 决策

1. 首期 Rust 单进程服务，目标默认存储为嵌入式 DuckDB 2.0.0。
2. 复用已有网关，默认网关转换工程值并由服务端校验；不默认重写所有协议驱动。
3. 首先交付只读采集、实时状态和历史查询闭环；真实控制独立分期。
4. 设备 / 资源 ID 与 UNS 路径分离；质量、新鲜度和连接状态分离。
5. durable、幂等及恢复需按详细设计验证；没有验证的场景不得承诺无损。
6. 外部 TSDB、WoT / Sparkplug 适配和 MCP 按需求与测试阶段逐步引入。

## 后果及待验证

部署简单，但必须验证 DuckDB 工作负载、磁盘可靠性和 WAL 恢复；现有网关能否携带稳定消息 ID 与绑定版本决定可靠模式是否可用。详细定义以 [设计规范](../architecture/design-specification.md) 为准。
