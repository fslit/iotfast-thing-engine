## 1. 如何启动

- 若计划已合并：从最新 main 分支启动；若计划仍只在 PR：先获取该 PR 的实际 head 和 main，明确读取的是计划分支，不要在 main 假设文件已存在。开发基线依具体任务与依赖状态确定，禁止直接覆盖用户已有改动。
- 开始前记录 main SHA、计划所在 SHA、未合并 PR、当前 HEAD 和工作区状态；不可用项标 BLOCKED。每次一个小任务、一个独立分支/PR，编号为工作包编号，不表示 GitHub Issue 已创建。
- 报告状态 PASS、FAIL、BLOCKED、NOT_RUN；每项记录真实命令、工作目录、环境、退出码、测试数量、证据路径。测试未运行不能作为通过。
- F00 复核结果可以含明确阻塞，只有下游所需的前提被阻塞时才阻止该下游任务。F01 确认目录及必要构建前提后启动 F02；实际认证/现场/目标库缺失不得用于生产验收，但可并行完成不依赖它的设计。
