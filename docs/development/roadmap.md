# 研发路线与任务

权威任务定义及详细验收见 [设计规范第 27 节](../architecture/design-specification.md#27-功能任务拆解与验收用例)。本路线是工作顺序，不代表任务已完成。

| 任务 | 依赖 | 交付与核心验收 |
|---|---|---|
| D00 契约冻结 | 无 | ✅ 梳理术语、字段、JSON 样例、错误及冲突；完成评审。 |
| D01 工程与构建 | D00 | ✅ Rust 工程、配置与健康检查；记录实际 Rust / DuckDB crate / 引擎版本。 |
| D02 产品和物模型 | D01 | ✅ 草稿、验证、发布、不可变版本。 |
| D03 资产与 UNS | D02 | ✅ 资产树、设备、资源稳定 ID、路径变更。 |
| D04 来源和绑定 | D02、D03 | ✅ 服务身份及可信数据范围、绑定版本、校验与激活。 |
| D05 数据入站 | D04 | ✅ 工程值、质量、整消息原子校验和绑定版本核对。 |
| D06 持久与幂等 | D05 | ✅ 应用日志、持久确认、去重和崩溃恢复；完成前只能提供 volatile 语义。 |
| D07 状态与历史 | D06 | ✅ DuckDB 历史、事务 / 去重和 latest 投影。 |
| D08 北向查询 | D07 | ✅ 影子、实时快照衔接、历史查询和限额。 |
| D09 网关联调 | D08 | 模拟器或指定真实设备至画面的端到端闭环。 |
| D10 验收和运维 | D09 | 故障测试、性能报告、配置与恢复说明。 |
| D11 上层 MCP 集成 | D09 | 上层按需封装；引擎提供范围受控的数据接口，不内置 Agent。 |
| D12 设备控制 | 上层另行规划 | 控制、审批和联锁不属于本引擎。 |

D00 的具体待决策事项及验证向量参见 [D00 契约评审清单](d00-contract-review.md)；内容仍为候选方案，未完成实际验证。

## 真实项目待确认

现有网关接口及重传机制、首个实际设备点表、目标硬件与负载、数据保留与允许丢失窗口、身份系统、外部 TSDB 首选。可先用明确标注的模拟数据推进，不得当成现场结论。
