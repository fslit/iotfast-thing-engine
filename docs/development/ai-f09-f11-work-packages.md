## 2. F09 — 模拟网关到标准数据服务闭环

### F09-A 场景资产和样例

**输入**：F03 的机器契约和向量、F04 的测试身份配置、F05–F08 已实现接口。建议交付目录：

| 路径（相对已确定正式工程） | 职责 |
|---|---|
| `tests/fixtures/demo/` | 虚构模型、两台泵、绑定、遥测和来源状态的版本化样例 |
| `tests/integration/` 或实际测试 crate | 调用真实本地进程/API 的断言；Cargo 明确发现该测试 |
| `tools/gateway-simulator/` 或独立测试包 | 非生产模拟器，生成固定 ID、序列、时间与预设故障 |
| `docs/runbooks/` | 本地演示、排障、备份与恢复；路径由 F01 决定 |

模型至少包含一项压力、一项功率和一项状态；单位、类型、虚构数值及顺序写入 fixture。两台设备分别绑定同一模型、不同设备与数据来源；标识、tenant、scope 和消息 ID 可重复。模拟器不能把协议采集、现场数据或安全凭据当作已实现。

### F09-B 确定性的正向闭环

在临时目录和 loopback 上启动引擎及测试身份方；记录程序版本、端口、配置摘要和测试时钟。按真实契约执行：

1. 创建并发布模型 → 创建资产和两台设备 → 配置来源授权、绑定和激活。
2. 发送 pump-A 压力 0.42 MPa 和 pump-B 压力 0.51 MPa（虚构工程值），记录每次稳定消息 ID、ACK 状态与查询状态；确保不对工程值再次倍率换算。
3. 使用经过验证的不同服务 Scope 查询设备 view、历史与订阅；断言设备、属性、单位、采样时间、来源、质量和模型/绑定版本正确，越权属性和设备不可见。
4. 查询区间、排序与是否产生历史记录以实际已冻结的存储/死区策略为准；预先配置能产生两条预期记录的策略，不能通过调整断言掩盖丢数。
5. 上报 source_state 断线事件：核对来源状态和新鲜度变化，历史工程值记录数及旧采样时间不应因断线被伪造更新；发送恢复和新测量后继续查询。
6. 清理只属于测试的临时进程、目录和网络资源；保留脱敏日志、请求/响应和断言结果。

### F09-C 故障和鉴权矩阵

| ID | 注入 | 必须观察 |
|---|---|---|
| SIM-01 | 相同 key、相同内容重试 | 依契约 duplicate，返回关联状态；无重复有效观测 |
| SIM-02 | 相同 key、改变 payload | 明确冲突，原记录及最新值不被覆盖 |
| SIM-03 | 任一点位非法 | 整消息拒绝、无部分观测或 WAL 成功确认 |
| SIM-04 | 持久成功后响应丢失/超时再重试 | 同 ID 幂等，按原结果或当前状态返回 |
| SIM-05 | 服务进程终止/重启 | 观察 WAL、历史、checkpoint 恢复；进程终止不代表物理断电 |
| SIM-06 | 错租户、过期凭据和只读权限写入 | 拒绝访问、不能泄漏另一个 scope 的数据 |
| SIM-07 | 快照期间并发更新、慢客户端 | 连续可解释或明确 resync；不能静默声称事件无损 |
| SIM-08 | 磁盘或同步故障（可控注入） | 按约定失败/背压；不得误报 durable |

每个 case 记录输入、注入位置、预期响应、数据库/WAL/业务视图断言、恢复后状态、命令及结果。测试中断保留环境和首个失败，不自动覆盖。可注入故障和真实文件系统故障分别标识。

### F09-D 运行和恢复手册

提供可从干净环境执行的 build/start/test/stop、配置键和依赖、健康/ready、日志及指标、数据保留和权限、故障排查、备份/恢复与版本升级回滚。不得只写“备份整个目录”：列出何时停写/停止进程、哪些配置/元数据/数据库/WAL/checkpoint 形成一致恢复点、每一步校验和恢复演练结果；运行中一致性未验证时明确要求停机并标限制。

**完成条件**：场景和 SIM-01–08 可重跑；列实际执行环境、命令、通过失败及证据，测试数据全虚构。本阶段不能宣称真实网关、生产安全、物理断电或性能合格。

## 3. F10 — 真实网关、现场与发布评估

### F10-A 输入与职责确认

| 输入 | 最低内容 | 缺失处理 |
|---|---|---|
| 测试授权 | 指定隔离网关、地址/端口和允许读写动作；只读采集 | 没有授权则不连接 |
| 网关能力 | 软件版本、协议/报文样例、设备时钟、序列、重试、持久队列及重启行为 | 先发差异表，稳定身份缺失时可靠语义 BLOCKED |
| 首批点表 | 脱敏设备标识、属性、类型、单位、倍率归属、质量、采样频率 | 可用虚构例子准备，不标现场已验证 |
| 部署环境 | OS/架构、CPU、内存、磁盘/文件系统、网络/断网、备份 | 指定目标与隔离数据目录 |
| 验收阈值 | 稳态/峰值吞吐、p95/p99、错误率、保留期、恢复目标和容量 | 未约定只报告测得值，不判通过 |
| 故障演练 | 可操作范围、窗口、终止条件、备份/恢复负责人 | 故障未获准不得注入 |

### F10-B 真实协议映射与幂等核验

记录 raw protocol value → 网关工程值 → 引擎 telemetry → 北向视图的字段对应、时间来源、质量码、source_seq/epoch 和模型/绑定版本；现场按脱敏样本核对类型、单位、倍率。引擎仅使用网关工程值。

验证设备断开/恢复、网络超时、同一 key 重试、网关重启、断网缓存与补传、绑定切换；分别记录 gateway 侧源 ID/序列和引擎 ACK/历史。网关无稳定标识时提出独立持久桥接方案及试验，不临时生成随机 ID 并宣称重试幂等。

### F10-C 可复现负载与故障实验

先写实验清单：目标、目标机器、版本、点位/设备/批次/值变化与质量分布、采样间隔、持续时间、预热、并发、负载发生器、独立监测、时间同步与可容忍误差。至少报告入站延迟、端到端可见延迟、p50/p95/p99、吞吐、失败/重复/丢失、CPU/内存、磁盘写入与容量、WAL 积压、恢复耗时；给统计窗口、样本量、百分位算法和是否包含排队。

使用不同运行标识及隔离数据库；对比发送日志、ACK、持久记录与查询结果，说明哪些结果只能证明应用层而不能证明磁盘断电。单独列 SIGKILL、进程崩溃、网络中断、磁盘满、备份恢复、物理断电；只有得到授权和硬件条件才能运行物理断电，不等同于 kill -9。

### F10-D 发布候选交接

提交版本/构建来源、OS 架构与依赖、配置、迁移路径、兼容矩阵、安全身份与证书轮换、容量与保留、监控告警建议、备份恢复验证、故障处置、升级与回滚。逐一记录功能/安全/可靠性/性能/现场验收状态，列责任人与可追踪问题；未满足目标时输出修复计划与发布阻塞，不将“模拟通过”当现场验收。

## 4. F11 — 外部 TSDB 统一接口与单库验证

**必读**：[TSDB 共性与差异接口](../specifications/tsdb-common-extension-interface.md)、[外部引用映射](../specifications/external-tsdb-reference-mapping.md)、[存储适配器契约](../specifications/storage-adapter-contract.md)。先选一个实际数据库、服务端版本、客户端版本、部署方式及受控测试实例；TDengine/InfluxDB 等只作为候选，不预设支持。

### F11-A 统一能力和调用契约

| 能力维度 | 必须记录 | 降级或拒绝 |
|---|---|---|
| 时间与排序 | 精度、时区、区间语义、同时间戳及稳定排序键 | 不能区分同毫秒事件时披露冲突或拒绝严格分页 |
| 身份与质量 | 原生 observation_id/质量是否存在和保真 | 不得把合成 ID 当原始稳定 ID、未知质量当 good |
| 读查询 | 点查/区间/过滤/聚合/分页、超时与成本 | 不支持的条件拒绝或明确标注经引擎处理 |
| 写和确认 | 批量部分结果、确定失败/不确定、持久保证 | 未知结果不报成功，重试需证明幂等 |
| 管理与安全 | 只读账号、命名空间、连接/凭据引用、超时/配额 | 不开放任意 SQL、用户自定义连接或跨 tenant 查询 |
| 证据 | DB、驱动、适配器版本、配置、时间、测试与限制 | 版本或配置变更后重新验证能力快照 |

能力声明以目标版本及配置实测为准；健康连接不证明可持久写入或查询完整性。扩展能力以命名和版本暴露，不能突破 Scope 和统一 API 限额。

### F11-B referenced_read 只读引用

建立数据源连接版本、可信发现/核验的源对象、字段到 resource_id 的版本化映射、生效时间、源字段类型/单位/质量和转换策略；明确权限、凭据引用、运行时断开、映射重发布与历史区间。参数化查询或安全的厂商 API；动态标识符须白名单与验证，不能接受普通用户任意 SQL。

测试无质量、源字段删除/改类型、非法单位、单位转换一次且不重复、source unavailable、跨租户引用、历史区间切换、同时间戳和分页。它不隐含本地 WAL、数据副本、持续订阅、写入或断网补传。

### F11-C managed_ingest 投递

在 P0 已 durable 接收之后，按独立 target 的能力记录投递任务、重试、错误和位置；本地 ACK 与目标提交是不同状态。验证完全成功、明确失败、部分成功、超时结果未知、重启和重复投递：每条稳定 observation_id 在目标端的去重保证必须实际验证。若目标不能区分相同时间戳/缺唯一键，明确可能重复/覆盖，拒绝声称 exactly-once。测试环境为真实数据库实例时提供启动/清理方式、版本和隔离策略。

## 5. F11 — OEE、能耗与模型的数据契约

**必读**：[衍生指标、OEE 与能耗设计](../specifications/derived-metrics-oee-energy.md)。这部分是独立上层算法集成/受限派生设计，P0 不依赖算法服务。所有公式为示例，先由 MES/EMS 明确口径，禁止让 AI 选择现场未确认参数。

### F11-D 最小数据模型和血缘

逐个确认 MetricDefinition、AlgorithmRevision、MetricBindingRevision 和 MetricResult 的权威字段与兼容策略，再生成 schema/表；每个结果至少表达目标 resource、数值/单位、质量与状态、时间窗口、输入引用或可追溯快照、算法/配置版本、计算时间和来源。迟到、重算、幂等键与版本生效期明确后才写入结果；无输入或分母为零返回不可计算/未知，不能虚构 0 或正常值。

简单公式只能引用经授权资源、确定性算子与受限资源配额；依赖图需检测环、运行超时和输入缺失。复杂业务计算由上层服务做，输出经服务身份/Scope 校验并保留血缘。禁止算法触发物理设备控制。

### F11-E OEE 验证案例（虚构）

MES 提供计划生产时间、运行时间、理想周期、总产量、合格数及班次窗口；设备模型提供运行状态及相关事件。约定样例：计划生产 480 分钟、运行 420 分钟、理想周期 0.5 分钟/件、总产量 720、合格 684。

在确认本案例口径下：可用率 = 420/480 = 87.5%；性能率 = (0.5×720)/420 ≈ 85.714%；质量率 = 684/720 = 95%；乘积 OEE = 71.25%。测试需检查分钟/秒单位换算，若质量数不合法、时间重叠或产量不可用则按确认的质量策略拒绝/标未知；性能率是否允许超过 100%、计划停机是否排除、跨班次/时区与迟到重算均应由业务规则决定，不能硬编码。结果带算法、班次/输入快照版本及权限范围。

### F11-F 能耗与节能验证案例（虚构）

电表提供期初/期末累计有功电量和质量；同计量范围内 1000 kWh → 1120 kWh 的区间消耗为 120 kWh。测试倍率/单位、计量点边界、换表、回零/溢出、缺失/坏质量、重复采样、时区及迟到重算。换表或回零没有经确认规则时不能直接相减生成负能耗或假数据。

节能量是基线与实际消耗在可比条件下的差值：基线、环境/产量等调整项、方法版本及验证期须来自 EMS/专业服务。没有可比基线时输出“无法评估”，不能把低用电直接称为节能效果。
