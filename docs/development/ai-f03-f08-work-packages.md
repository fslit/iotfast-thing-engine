# AI 开发工作包：F03–F08 核心数据引擎

状态：待执行的研发计划。基于 main `c0a5a42d247c66e66e94475ad7a5d0abd210e1b3` 和 [AI 任务拆解](ai-implementation-work-breakdown.md)；正式工程、机器契约和测试尚须实现。本文列交付与验收，不替代 [规范入口](../specifications/README.md) 指定的权威设计；发现矛盾先登记、修订权威规范和向量，再编码。

## 1. 执行方式和阶段依赖

F03 建立公共契约，F04 在真实认证验证边界上落实 Scope；F05 建立控制面与资产绑定；F06 完成事件接收及 WAL；F07 建立历史和投影；F08 完成北向网络接口。F03、F05 的部分纯领域工作可在 F01 决策、F02 基础结构完成后并行，但公共契约/路径和所有权要先明确；不得借助模拟鉴权开放生产入口。

| 工作包 | 前置 | 小任务与可审阅交付 |
|---|---|---|
| F03 | F01、F02 | A 规范对账与向量；B DTO/Schema；C 派生与跨语言验收 |
| F04 | F03 与身份方案 | A 认证；B 授权与审计；C 真实网络负例 |
| F05 | F01/F02、F03；对外入口依赖 F04 | A 模型；B 资产/UNS；C 来源/绑定与审计 |
| F06 | F03/F04/F05 | A 验证/幂等；B WAL/ACK；C 源状态与恢复 |
| F07 | F06 | A 表与事务；B latest/重放；C 历史/分页 |
| F08 | F04/F05/F07 | A HTTP/view；B 快照衔接订阅；C 网络验收 |

单任务输出包含目标分支 SHA、输入规范及代码、范围内文件、测试命令/环境/退出码、行为证据、风险和回滚。每次只认领一个有界小任务；并行时先冻结跨任务接口及文件所有权，冲突修改串行。真实网关、签发方、负载或平台缺失时将对应验收标 BLOCKED，允许不依赖这些输入的子任务继续。不得把 fake、内存适配器和旧报告称为网络、断电或生产验证。

## 2. F03 — 遥测公共契约与确定性身份

**必读**：[服务身份与 D00](../specifications/service-identity-and-scope-contract.md) 第 4–8 节、[P0 遥测](../specifications/p0-telemetry-contract.md)、[D00 集成蓝图](../specifications/d00-integrated-implementation-blueprint.md)、prototype/src/d00.rs、prototype/feasibility/f1_d00_contract/ 实际向量及脚本。

### F03-A 契约对账和黄金向量

1. 逐字段建立来源、类型、必填/缺省/null、可变性、授权来源、摘要参与规则及错误清单，覆盖 telemetry、source_state、错误信封。
2. 核对 observation_id 的字节编码和分隔方式、排序、hash 算法版本、int64/u64/二进制浮点、Unicode、重复 JSON 键、时间与版本切换。发现规范和现有向量不一致，先记录差异与影响，不自行选一边生成代码。
3. fixtures 中同时保存原始输入、期望规范化字节（或十六进制）、摘要、派生 ID 与预期错误；固定输入编码和版本，禁止从被测函数动态计算期望值。

### F03-B DTO 与机器契约

- 按 F01 选定的目录生成版本化 DTO、JSON Schema、标准错误结构；将解析错误、字段约束和模型/授权等运行时规则分层。Schema 不能表达的约束写成明确的语义测试。
- 将 points 去重、非空、类型与有限数、固定 spec、source_seq 十进制范围和时间字段按权威契约校验。禁止未经检查的截断、溢出、非有限数及重复 JSON 键悄悄通过。
- Schema、示例和 DTO 均需在 CI 同一固定 fixtures 上验证；尚未解决的字段/错误码必须明确 BLOCKED。

### F03-C 跨语言和测试矩阵

| 用例 | 预期 |
|---|---|
| 同一消息反复重试 | observation_id 与业务摘要稳定；传输重放标记遵循契约排除 |
| 多点输入不同顺序 | 按冻结规则得到一致的规范化结果 |
| 内容改变但 key 不变 | 后续 F06 判冲突，不能误报 duplicate |
| null / 缺失、整数上下限、-0、Unicode、重复键 | 与版本化黄金向量一致或明确拒绝 |
| 同样身份在不同 tenant/source/epoch | 使用正确命名域，不能串用 |
| Rust 与现有 Python 测试向量 | 对同一固定输入逐字节、逐摘要比对 |

验收：Rust 和 Python 均为实际执行结果；真实网关语言未提供时另记 BLOCKED。提交向量变更必须附版本和旧数据/旧网关兼容策略，不能静默覆盖旧向量。

## 3. F04 — 服务身份、Scope 和隔离

**必读**：服务身份规范第 2–3、7 节；北向规范第 1、5–8 节；F01 身份决策。

### F04-A 认证边界

- 依据 F01 选定的受信签名令牌或 mTLS 验证器，校验证书/签名、算法、信任锚、issuer/audience、有效期与凭据来源，适用项及撤销、轮换取决于实际选型；拒绝不支持的算法和无凭据请求。
- 验证结果才可创建内部可信上下文；客户端正文、header 和 URL 中自报字段只能与可信身份对照，不能扩权。测试替身只用于测试，默认不启用并明确不能用于生产。
- 服务健康接口与业务接口边界以 ADR 定义；诊断接口不暴露租户信息、存储路径或凭据。

### F04-B 授权矩阵和审计

| 调用方 | 代表动作 | 必须验证的范围 |
|---|---|---|
| southbound_source | telemetry:ingest、source_state:report | 已认证 source、tenant 与设备授权 |
| management_service | model/asset/device/binding/source 写 | 管理域、动作、资源关系、审计 |
| northbound_service | catalog/view/shadow/history/subscription 读 | 动作和资源过滤、属性裁剪 |
| catalog_reader | 只读目录/视图/历史 | 指定只读范围和限额，拒绝写 |

每次先验证身份、有效期、租户和动作，再依据权威契约处理非空范围维度的组合与资源匹配；禁止先分页/聚合后过滤。缓存、cursor、WS 都绑定身份和 Scope；撤权/过期依契约再鉴权或断开。鉴权失败的日志不泄露目标资源是否存在；业务审计的写入与数据库变更原子边界依 F01 决策验证。

### F04-C 验收

覆盖无凭证、错误签名/信任锚、过期/未生效、错 audience、非法算法、空 scope、错误动作、跨租户、子树/URI 段边界、部分属性、缓存/分页/聚合、长连接失效。至少执行一种真实传输与真实测试凭证的端到端测试；外部生产身份方尚未接入时单独标 BLOCKED。证明权限矩阵由各入口调用，不靠人工约定。

## 4. F05 — 模型、资产、来源和绑定

**必读**：[设备业务模型](../specifications/device-business-model.md)、[数据库表结构](../specifications/database-schema-design.md)、北向规范第 2–4 节、F01 数据所有权 ADR。

### F05-A 模型目录

- 草稿创建、语义校验、发布与不可变快照；唯一性和并发条件由数据库约束配合事务保障。
- 单事务内固化模型正文、摘要和属性索引；发布失败回滚。比较属性增删、类型、单位和语义变化；破坏性变更不可静默覆盖现有设备历史。
- 测试同版本并发发布、重复属性、非法单位/类型、发布后修改、事务失败、读历史版本；测试管理写 Idempotency-Key 的重试和冲突。

### F05-B 资产、设备和 UNS

- 验证同租户产品/模型/资产关系，设备实例化时原子创建属性资源。稳定 ID 不依赖可变路径；迁址须保留重定向及期限，URI 段边界和不可复用规则遵循现有规范。
- 测试形成父子环、同级 slug 冲突、迁址冲突、旧路径锁期、事务中断、部分 Scope 设备视图以及标识碰撞/长度/字符约束。
- 运行数据库迁移前比较实际 schema、备份与回滚策略；数据升级失败不得宣称完成。

### F05-C 来源与绑定

- 来源授权、草稿校验、网关确认及激活按权威状态机实现；激活要保证同设备有效绑定的不变量。网关确认与数据库不具备共同事务时，定义重试、对账、停采与失败恢复。
- 历史消息使用其绑定快照，重试按 D00 规则；不允许将 gateway-normalized 工程值再次缩放。
- 验收：两台虚构泵实例；绑定变更中断/重复 ACK/并发激活、旧版本重试、未授权来源和审计回滚。元数据事务与审计关系给出实测结果。

## 5. F06 — 入站原子性、WAL 与质量事件

**必读**：P0 遥测、D00 公共契约第 4–6 节、[存储适配器契约](../specifications/storage-adapter-contract.md) 和详细设计 21–23 节。

### F06-A 验证、幂等与并发

1. 接收真实传输后校验身份、tenant/source/device 授权、报文结构、消息与所有点位类型/模型/绑定；失败不能部分写入。
2. 按规范处理已知 key 和新 key，比较固定 payload_hash 与历史绑定快照；同 key 不同内容冲突。同 key 并发必须有单一接受结果、稳定 ingest_id/observation_id，跨 scope 不共享。
3. 路由参数、错误类型和重试标记与机器契约一致；非法输入、过期授权和容量不足不通过默认成功响应。

### F06-B WAL 和确认边界

- 写出每步持久状态图及顺序：帧编码/校验、写入、同步、确认、投影、checkpoint、重放；区分同步文件、目录和底层硬件持久能力。
- 请求 durable 无法满足时显式失败，不降级。volatile 不写成 durable 或虚构 WAL 位置；durable ACK 不等于 DuckDB 历史已提交。调用方超时后使用相同 key 重试。
- 故障注入点至少覆盖写前、帧中、sync 前/失败/后、响应前、数据库提交前后、checkpoint 前后；每点列预期 ACK、WAL、历史、恢复结果。中间损坏与不完整尾部按契约区分。

### F06-C 状态事件

- 测量与 source_state 使用独立消息类型和幂等域。连接超时只能变更来源/相关质量与新鲜度，不伪造工程值或新采样时间；乱序状态不覆盖较新状态。
- 至少验证整批中单点错误零副作用、重试成功与冲突、磁盘满/同步失败、并发竞态、WAL 截断/损坏、旧绑定重试、授权撤销。
- 验收记录进程 kill、模拟 I/O 失败和实际断电分别进行；未实测硬件掉电明确 NOT_RUN，不由 sync 调用推导物理保证。

## 6. F07 — DuckDB 投影与历史查询

**必读**：数据库表结构、详细设计 23–24 节、时序存储及存储适配器契约。

### F07-A 表结构及单库事务

- 按版本化迁移建立历史、消息应用记录和必要索引；记录实际 DuckDB 版本、链接方式、模式迁移与回滚。SQL 使用参数绑定；范围查询在 SQL 或等效受控查询中先过滤后统计与分页。
- 单一事务中处理适用的历史行、去重记录及投影基准；只对该数据库的真实事务范围作保证。与 WAL/checkpoint 的跨域顺序和崩溃恢复必须有测试。
- 确定 timestamp、observation_id、单位、模型/绑定快照和质量的保存方式；检查同毫秒不同观测不覆盖。

### F07-B 恢复、latest 与质量

- checkpoint 仅前移已连续确认的前缀；重复回放不产生重复观测；旧采样进入历史但不可覆盖较新 latest。值、来源状态、质量与 freshness 分开。
- 构造同源同时间、跨来源、乱序和相同排序键的案例；对排序规则不足的情况先修订权威规范，不在实现中随意挑最后写入。
- 在数据库提交前后杀进程、重放多次、注入重复和间隙，验证重启结果；死区/心跳不得抹除质量变化。

### F07-C 查询与 cursor

- 半开时间区间、按权威契约排序、上限、质量过滤与 scope；稳定排序至少区分同毫秒不同观测。cursor 包含查询指纹、范围和过期信息，采用标准 HMAC 或经审查的 AEAD/签名库。
- 测试篡改 cursor、跨 Scope/查询复用、过期、密钥轮换、迟到数据、空窗及增删变化；若跨页一致性不能保证，应按接口约定明确说明或拒绝，不凭 cursor 声称数据库快照。
- 只在能证明时提供事件时间覆盖水位；WAL 水位不是事件时间完整性证据。

## 7. F08 — 北向只读 HTTP 与 WebSocket

**必读**：北向规范第 5–9 节、服务身份规范第 3 节及 F04/F07 证据。

### F08-A 网络 API

实现资源目录、设备 view/shadow、history 查询与 ingestion 状态等已确定的接口；对各端点固定身份、动作、过滤、请求上限、排序、响应错误及超时。OpenAPI/Schema 与真实 HTTP 响应以及示例使用同一份版本化 fixtures 核验。

view 按资源授权逐属性裁剪；无采样返回 unknown/null，不能把旧值或断线标为实时正常。历史分页、限额、错误与 coverage 不得泄露被隐藏数据的计数。

### F08-B 快照与增量

对单个受控有序域捕获快照边界 S 和对应状态，缓冲并按契约发送 S 之后增量；明确并发原子性、重启 epoch、缓冲上限、去重和客户端恢复语义。溢出、鉴权失效或不能保证连续时明确通知重同步。仅状态合并不代表事件无损。

### F08-C 实际网络验收

| 场景 | 可观察的验收结果 |
|---|---|
| snapshot 与并发更新 | 更新可由边界及后续消息解释，无未披露缺口 |
| 消费缓慢/缓冲溢出 | 明确重同步，不静默丢事件 |
| 断连/重连、服务重启 | 根据协议重新同步，不复用过期顺序域 |
| scope 收窄、凭证到期 | 停止泄露被撤销资源，并执行契约规定的重鉴权或断开 |
| 混合可见与不可见属性 | 视图、分页、聚合、cursor 均不泄露不可见资源 |
| 错误/超限请求 | 限额与错误码符合机器契约，日志不含凭证 |

用真实本地 TCP 和 WebSocket 客户端执行，记录平台、命令、端口隔离和结果；单元函数调用不能替代网络验收。无法达成可证明的快照一致性时不宣布该接口可用于生产。
